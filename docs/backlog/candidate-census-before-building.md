# no census of complete candidates before a linter is built

The number of functions, tables or fields is not the number of candidates with both halves present.
Several ideas in this backlog looked large until a scan showed unit tags with no docs, deep-copy
promises with no tests, and similar backend tests with no shared scenarios.

The idea: a light inventory per idea that records supported, partial and absent shapes with a few
checkable examples, and feeds the worth call. It is input to the decision, not proof of useful findings.

Unknown that settles it: whether this belongs in the binary (a mode of the future extractor) or in a
script, and what it costs per idea.
