# eval does not show what each candidate exclusion costs

Removing a class of candidates makes precision look better at no visible price. Examples already in the
code: debug and info lines are not candidates for `destructive-remediation`, an action can excuse
`normal-event-at-error` once the error is established, an HTTP writer changes the doc question.

The work: tagged defects and negatives for each exclusion (including a real operator instruction at info
level) and a counter per exclusion in `lintuition eval`, so dropping a class shows as lost coverage, not
as a precision gain.
