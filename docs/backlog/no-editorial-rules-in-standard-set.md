# no editorial rules in the standard set

"A negative bool name is bad", "history belongs in the commit message", "Deprecated must name a
replacement", "every error deserves its own type" all have legitimate opposite cases, so none of them
goes into the standard set as a correctness rule. `error-needs-type` is already opt-in policy. An
editorial pack would need its own explicit requirements, kept apart from contradictions. The specific
rejections have their own items here.
